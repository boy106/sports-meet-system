# 16 · 报名表导入（v1.9.0 新增，v1.9.3 改为「模板直接上传」）

> **v1.9.3 重要更新**：下面描述的「Python 脚本转 JSON」链路**已不再是主路径**。
> 发行包里不含任何脚本，老师拿到 exe 后点「导入」其实无脚本可用 —— 这是
> 实测暴露的可用性缺口。现改为闭环：
>
> ```text
> 网页「报名表导入」→ 下载 Excel/CSV 模板 → Excel 填写 → 选文件上传 → 系统解析并入库
> ```
>
> 后端 `src/core/baoming.rs` 负责 xlsx（zip + sharedStrings + sheet XML）
> 与 csv 解析，产出 payload 后**复用 `Core::import_baoming`** —— 增量语义、
> 限额、性别分组、年级自动补、跳过报告一条不少。旧 JSON 入口保留兼容。
> 详见本文 §八。

## 一、为什么中间要转一道 JSON

Rust 版二进制**刻意不解析 xlsx**：为一个导入功能引入几 MB 的解压/XML
依赖，会打破项目"单 exe 数 MB、零新增依赖、离线单机"的约束
（见 `docs/03` 目标文档）。所以链路是：

```
报名表.xlsx ──tools/baoming_import.py──▶ 报名表.json ──POST /api/import/baoming──▶ 系统
                    （只进源码包）              （网页端粘贴/上传，或脚本 --post 代发）
```

转换脚本**只进源码包**，与 `tools/issue_license.py`、`tools/integrity_stamp.py`
同一性质：发行包里没有任何脚本，攻击者拿到发行包也无从获得"导入能力"之外的
任何东西（它本身不含秘密）。

## 二、报名表长什么样（按学校实际模板）

```
第 1 行   大标题（忽略）
第 2 行   表头：序号 | 姓名（男） | 班别 | 100米 | 200米 | ... | 备注     ← 男生节
第 3 行+  数据行
第 15 行  表头：序号 | 姓名(女） | 班别 | 100米 | 200米 | ... | 仰卧起坐   ← 女生节
第 16 行+ 数据行
第 28 行  脚注（各班一名同学只允许报名2个项目……）                          ← 自动忽略
```

脚本的容错设计：

| 情况 | 行为 |
| --- | --- |
| 一张表里男女两节（列布局不同） | **每节分别识别**（男生节 1000米/引体向上，女生节 800米/仰卧起坐） |
| 姓名含"示例"的行 | 跳过（模板自带示范数据）并计数 |
| 项目列单元格是勾选标记 | 非空且为 `√ ✓ ✔ ● ○ Y y 是 1 / 报名 / 参加 / 参赛` 算报名；`×` **不算**（它更像"划掉"） |
| 班别"奥创七7" | 年级=奥创七、班号=7（另支持"初一（7）班""初一7班"写法） |
| 班别解析失败 | **不猜**，进报告单列一行，其余行照常导入 |
| 性别 | 优先"姓名（男）"括号提示 → 其次"性别"列 → 都没有留空（系统不按性别拦它） |
| 备注列 | 原样带进报名记录 |

## 三、项目名怎么对上系统里的项目

系统空库启动会预置 21 个项目（男子100米/女子100米/…/4×100米接力），
报名表列名与项目名**写法不一致**是常态（"100米" vs "男子100米"、
"4×100米" vs "4×100米接力"）。匹配策略（`--server` 时在线做，
把项目 id 直接写进 JSON）：

1. **名称完全一致**；
2. **归一化一致**：去空白、去「男子/女子/男/女」前缀、`×` 统一为 `x`、
   去尾部「接力」；
3. **按性别优选**：多个候选时，男生优先男子项、女生优先女子项、再通用项
   （"跳绳"对男生进"男子跳绳"、对女生进"女子跳绳"）；
4. 仍匹配不上的列：**在报告里列出来**，相关报名不生成——不静默丢弃，
   也不会瞎猜导进错项目。

不匹配时还有两条出路：在系统里先建同名项目；或用 `--event-map`
显式指定（`--event-map "100米=男子100米;4×100米=4×100米接力"`）。

系统端（`import_baoming`）还有一道**归一化兜底**：JSON 里只有名称没有
id 时（比如手写 JSON），按同样规则匹配；仍找不到就进 skipped 报告。

## 四、导入是增量的，可以重复跑

`POST /api/import/baoming` 的语义：

1. `ensure_grades: true` 时，把 `grades` 里缺的年级**自动加进设置**
   （"奥创七"这类学校自定义年级名不用先去设置页手工加；超 10 个上限会明确报错）；
2. 学生批量入库——**已存在的记 E_CONFLICT 跳过**（不覆盖、不报错中断）；
3. 按 (年级, 班号, 姓名) 解析学生、按 `event_id`/名称解析项目，逐条报名；
4. 全程复用既有校验：性别分组、每人单项/集体限额、每班每项限报、
   项目年级限制、重复报名检测——**任何一条不合格都进 `skipped` 报告**，
   不会半途中断，也不会绕过限制。

返回 `{ok, added, registrations_added, grades_added, skipped:[{name,reason,code}]}`。
重复导入同一张表：学生 +0、报名 +0，数据不翻倍（有单测守着）。

## 五、用法

```bash
# 1) 只转 JSON（不联网）
python3 tools/baoming_import.py --xlsx 报名表.xlsx --out 报名表.json

# 2) 转换并直接导入正在运行的系统（自动匹配项目 id；设了管理口令时带 --password）
python3 tools/baoming_import.py --xlsx 报名表.xlsx \
    --server http://127.0.0.1:8765 --password 口令 --post

# 3) 网页端：诊断页旁边的「班级与学生」页 → 报名表导入 →
#    粘贴 JSON 或选文件 → 解析并导入（报告同上有显示）
```

依赖：`openpyxl`（`pip install openpyxl`）。

## 六、诚实的边界

* 报名表**格式千校千面**。脚本按本校模板 + 常见变体设计，遇到全新格式
  会在报告里明说（班别解析失败/项目列未匹配），**不会静默导入错数据**；
  真遇到对不上的，改脚本比改数据快——它在源码包里，就是干这个的。
* xlsx 里的**公式单元格**依赖 Excel 缓存值；从没在 Excel 里打开保存过的
  表可能取到空值（openpyxl 的限制），让老师在 Excel 里开一下再存即可。
* 导入**不覆盖**任何既有数据。想推倒重来请用 v1.9.3 新增的
  「报名页 → 清空报名」（可按全部/项目/年级/班级），一次撤销全量恢复；
  它删的是报名条目，不是"撤销整次导入"，学生名单仍在（可重新报名）。

## 八、v1.9.3 模板直传链路

### 8.1 新增接口

| 接口 | 作用 |
| --- | --- |
| `GET /api/export/baoming_template` | 下载 xlsx 模板（表头列由当前系统项目动态生成，另带「填写说明」Sheet） |
| `GET /api/export/baoming_template?fmt=csv` | 下载 CSV 模板（同版式，带 UTF-8 BOM） |
| `POST /api/import/baoming_file` | 上传填好的文件：`{filename, b64}`（xlsx）或 `{filename, text}`（csv） |
| `POST /api/registrations/clear_preview` | 清空报名预检（不改动数据） |
| `POST /api/registrations/clear` | 按范围清空，需 `scope` + `confirm:true`，设口令时还要 `X-Confirm-Password` |

### 8.2 解析规则（`src/core/baoming.rs`）

版式判定与 Python 脚本同口径：**任何含「姓名」且非空列 ≥3 的行都是一节表头**，
节与节之间各自识别列布局。所以学校现成的男女分节旧表可直接上传。

* xlsx 读取复用 `rust_xlsxwriter` 已在依赖树里的 `zip` crate（提为直接依赖，
  依赖树不新增 crate），只解析 `sharedStrings.xml` 与第一个 worksheet；
  支持 `t="s"` / `t="inlineStr"` / 数字单元格与 XML 实体转义。
* 班别解析、勾选标记集合、示例行跳过、备注传递与脚本一致。
* 项目列匹配**按本节性别优选**：男生节「100米」→ 男子100米，
  女生节「100米」→ 女子100米；匹配上直接写 `event_id`，
  匹配不上只写名称并列入 `parse_report.unmatched_cols`，不静默丢弃。
* 请求体上限只对 `/api/import/baoming_file` 放宽到 8 MiB（xlsx 走 base64
  会膨胀 4/3），其余接口维持 1 MiB。

### 8.3 为什么没有引入 XML 库

xlsx 里只关心两张表的单元格，用有界字符串扫描即可。为一个导入功能拖进
整套 DOM 依赖，会打破项目「单 exe 数 MB、离线单机」的约束。

### 8.4 新增测试

| 测试 | 断言 |

| `baoming_template_xlsx_filled_roundtrip` | 生成的模板能被自己的解析器读回；模拟填表后 xlsx 上传→学生 +2/报名 +2/示例行跳过 2 |
