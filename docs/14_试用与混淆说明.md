# 14 · 试用密钥与混淆防逆向说明（v1.8.2）

> 本文回应四项需求：
> ① 内置免费试用密钥；② key 记录分散 10 份以上；③ 100 份以上假记录混淆；
> ④ 扫盘发现逆向工具就停止；并追加约束：**记录不能太显眼，要伪装成系统组件**。
>
> **先读第七节「诚实的局限」**——这里没有任何"无法破解"的承诺。

---

## 一、内置试用密钥

| 项 | 值 |
|---|---|
| 试用密钥 | `ky-2026tonghezhongxue` |
| 试用时长 | **30 分钟** |
| 使用次数 | **一次性**（每台机器一次） |
| 是否需要联网 | **否**（纯本地，靠分散记录实现一次性） |
| 存储形式 | 只存 XOR 混淆数组 `TRIAL_KEY_MASKED`，**二进制里无明文** |

密钥不落盘、不进日志；比对用**常量时间比较**（防时序侧信道），见
`trial.rs::const_time_eq_str`。

混淆数组由 `channel::obfuscate(b"ky-2026tonghezhongxue")` 编译期算出，
并由测试 `masked_key_roundtrips_to_plaintext` 守住与明文的一致性。

### 接口

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/aim/trial` | POST | body 可带 `{"key":"..."}`；不带则直接尝试启用 |
| 客户端 | `AuthManager::activate_trial()` | 启用试用 |
| 客户端 | `AuthManager::trial_status()` | 查询剩余时间 |
| 客户端 | `AuthManager::is_trial_key(key)` | 判断是否试用密钥 |
| 客户端 | `AuthManager::end_trial()` | 标记已消耗 |

## 二、记录分散：12 个真实位置

`REAL_SLOTS = 12`（需求要求 ≥10）。刻意**不集中在程序数据目录**——
那里只放 1 份兜底，其余散到用户可写的多个角落。

| # | 位置（Windows） | 文件名（伪装） |
|---|---|---|
| 1 | 程序数据目录 | `DiagnosticLog.db` |
| 2 | 程序 exe 目录 | `FontCache.dat` |
| 3 | `%APPDATA%\Microsoft\Windows\` | `usrclass.dat.LOG1` |
| 4 | `%APPDATA%\Microsoft\Crypto\RSA\` | `PerfDisk.dat` |
| 5 | `%LOCALAPPDATA%\Microsoft\Windows\Caches\` | `IconCache.db` |
| 6 | `%LOCALAPPDATA%\...\Explorer\` | `thumbcache_256.db.LOG1` |
| 7 | `%LOCALAPPDATA%\Packages\` | `StateStore.log` |
| 8 | `%PROGRAMDATA%\Microsoft\WMI\Settings\` | `PerfNet.dat` |
| 9 | `%PROGRAMDATA%\Microsoft\Diagnosis\` | `RegistryPolicy.dat` |
| 10 | `%TEMP%\` | `D3DSCache.log` |
| 11 | `%USERPROFILE%\Documents\` | `ShellCache.bin` |
| 12 | `HKCU\...\Explorer\FileExts\TrialPolicy` | （注册表项） |

Linux 下对应落到 `~/.cache/fontconfig/`、`~/.config/dconf/`、
`~/.local/state/dconf/`、`/tmp/.X11-unix/` 等（同样伪装命名）。

### 安全边界（必读）

> **伪装 ≠ 写系统文件。**
> 全部位置都在**用户可写目录 / HKCU 注册表**，**绝不**触碰
> `C:\Windows\System32`、`C:\Program Files` 或任何真实系统文件。
> 有专门的测试 `never_targets_real_system_directories` 守住这条线。

改名"像"系统组件只是为了让它在文件列表里不扎眼；物理位置始终在用户空间。

## 三、假记录：120 份

`FAKE_SLOTS = 120`（需求要求 ≥100）。特点：

1. **命名同源**：假记录也用同一套 `SYSTEMISH_NAMES` 名单 + 编号后缀，
   所以"按文件名筛"分不出真假；
2. **格式一致**：同一魔数 `\x89TRI` + 同一版本号 + 同一 `channel::seal` 加密帧；
3. **内容无关**：假记录的 `hwid_hash` 是 `fake-xxxx` 前缀，**永不属于本机**，
   解密验证时会被"指纹不符"排除，不干扰真实判定。

于是攻击者只能**逐个解密验证** 132 个文件才能定位真记录。

---

## 四、一致性模型

多份记录最大的风险是**互相矛盾**。本模块采用**最严格原则**：

```
读取（判定）：
  · 任一份 consumed == true        → 整体判定「已消耗」
  · 否则取所有记录中最早的 started_at → 对攻击者最不利
  · 任一份指纹与本机不符            → 忽略该份（可能是别处拷来的）
写入：
  · 同一状态写到全部位置
```

**效果**：删掉其中几份**不会**让试用复活（测试
`deleting_some_records_does_not_revive_trial` 守住）。
把记录从别的机器拷过来也无效（测试 `foreign_record_is_ignored`）。

### 记录本身的防篡改

每条记录有 `mac`（FNV 覆盖 `started_at` + `expire_at` + `hwid_hash` + `consumed`）。
改任一字段而不同步重算 MAC → 记录被拒。另叠加 `channel::seal` 的
16 字节 MAC（密钥由**位置号**派生，故各位置密文不同）。

测试 `slot_ciphertexts_differ_across_positions` 守住"各位置密文互不相同"——
否则同密文会暴露"这些文件是一伙的"。

## 五、反调试扫描（发现逆向工具就停止）

模块 `obf.rs`，入口 `obf::scan()` → `ScanReport { level, signals, score }`。

### 检测点

| 平台 | 检测 | 权重 |
|---|---|---|
| Windows | `IsDebuggerPresent` | 2 |
| Windows | `CheckRemoteDebuggerPresent` | 3 |
| Windows | `NtQueryInformationProcess`（DebugPort/Object） | 4 |
| Windows | 硬件断点 Dr0–Dr3 | 3 |
| Linux | `/proc/self/status` 的 TracerPid | 3 |
| Linux | `ptrace(PTRACE_TRACEME)` 失败 | 3 |
| 跨平台 | 执行时序异常（10 倍阈值） | 3 |
| 跨平台 | 调试器进程名（x64dbg/ida/frida…） | 1 |

### 分级响应（**关键**）

```
None   0 分   → 正常
Low    1-2 分 → 只记审计，不干扰
Medium 3-4 分 → 记审计，仍放行
High   ≥5 分  → 拒绝授权
```

**只有 `High` 才拒绝**，且要求多路强信号同时命中。

为什么必须分级？学校机房真实环境里有还原卡、极域/红蜘蛛电子教室、
360/火绒杀毒——它们都会触发调试类信号。**判太紧会误杀正常用户**。
测试 `normal_environment_is_not_high` 是防误杀的第一道闸。

落点：`AuthManager::activate_trial()` 开头先 `scan()`，
`High` 则拒绝并记审计；`status_json` 输出 `threat_level` / `threat_signals`
供界面展示。

## 六、混淆原语

| 原语 | 作用 |
|---|---|
| `opaque_true(seed)` / `opaque_false(seed)` | 恒真/恒假，但静态难判定 |
| `junk_math(seed)` | 无副作用假计算，`black_box` 强制保留 |
| `dead_branch(seed)` | 不可达分支，静态上"看起来会走" |
| `junk_strings(seed)` | 产出未使用的假串，干扰字符串检索 |
| `dispatch_key(state, seed)` | 控制流扁平化的分发键（保证是置换） |

`opaque_true` 的构造依据：**两个连续整数之积必为偶数**（`x·(x+1)`），
故 `(x·(x+1)) & 1 == 0` 恒真——但需一步数论推导，反编译器不会自动折叠。

> 注：早期版本用过 `b = a ^ (a >> 31); (b&1)==(a&1)`，**那不是恒真**，
> 已被测试 `opaque_true_is_always_true` 抓出并修正。见 `05_踩坑记录.md`。

## 七、诚实的局限（**必读**）

1. **纯本地的"一次性"不是硬一次性**。
   若攻击者反编译拿到全部位置清单，可一次性清空 132 个文件 + 注册表项。
   本方案把成本从"删一个文件"抬到"定位并清除 130+ 个分散文件"，
   但**不保证不可重置**。

2. **真正的一次性必须服务端参与**。
   `TrialPolicy::require_online_confirm` 是为此预留的开关：开启后
   试用密钥首次使用必须联网，由服务端登记"该指纹已用过试用"，
   服务端拒绝重复登记 —— **那才是硬一次性**。当前默认**关闭**。

3. **反调试挡不住内核态调试**（WinDbg 内核调试、Hypervisor 隐藏），
   也挡不住"先 hook 我们的检测函数再喂假结果"这种针对性对抗。

4. **假逻辑只抬高静态阅读成本**，动态调试器下单步即可看穿。

5. **任何客户端防护都可被绕过**。
   本模块的定位是"**让白嫖变麻烦且可追溯**"，不是"无法破解"。
   与 `12_密钥与防破解说明.md` 的立场一致。

## 八、测试覆盖

`trial.rs` 19 个单元测试（全绿），覆盖：

| 测试 | 守住什么 |
|---|---|
| `trial_key_matches_and_rejects_others` | 密钥匹配 + 拒绝近似的错误密钥 |
| `masked_key_roundtrips_to_plaintext` | 混淆数组与明文一致 |
| `trial_is_one_shot` | **一次性** |
| `expired_trial_is_rejected` | **30 分钟时效** |
| `deleting_some_records_does_not_revive_trial` | 删记录不复活 |
| `real_slots_are_at_least_ten` | **真实位置 ≥10** |
| `fake_records_exceed_100` | **假记录 ≥100** |
| `slot_ciphertexts_differ_across_positions` | 各位置密文不同 |
| `record_filenames_look_like_system_components` | **伪装成系统组件** |
| `never_targets_real_system_directories` | **不碰真实系统目录** |
| `fake_and_real_records_share_format` | 真假记录格式一致 |
| `foreign_record_is_ignored` | 跨机拷贝无效 |
| `tampered_record_is_rejected` | 密文篡改被拒 |
| `record_mac_catches_field_tampering` | 字段篡改被拒 |

`obf.rs` 8 个单元测试，覆盖恒真谓词、置换性、分级阈值、正常环境不误判。

### 测试隔离（重要工程实践）

`TrialManager` 的位置解析走 `PathRoot` 抽象：
生产用 `PathRoot::Real`（读真实环境变量），测试用 `PathRoot::Fake`
（全部落到临时目录）。否则测试会互相污染，也会污染开发者真机
（这是实际踩过的坑，见 `05_踩坑记录.md`）。
