## 0.2 为什么单独做"双端契约测试"（`tests/wire.rs`）

客户端与服务端**各持一份 `channel.rs` 副本**，编译期互不可见。
编译器**无法**保证二者仍兼容 —— 谁改了盐或帧布局，两端照样各自编译通过，
却再也说不上话。因此 `wire.rs` 绕开抽象，**直接读磁盘上服务端源码文件**：

| 测试 | 守住什么 |
| --- | --- |
| `frame_magic_matches_server_source` | 帧魔数 `SMAF` 两端一致 |
| `session_key_salt_matches_server_source` | 盐的混淆字节两端逐字节一致 |
| `deobfuscation_is_deterministic` | 混淆/还原严格互逆 |
| `sealed_frame_has_stable_wire_layout` | 帧布局（大端、各字段偏移）稳定 |
| `derivation_is_deterministic` | 派生确定、参数顺序参与运算 |
| `full_handshake_roundtrip_via_server_perspective` | **模拟服务端视角跑通完整握手** |
| `wrong_psk_cannot_open_frame` | 错误 PSK 解不开 |
| `tampered_transit_frame_is_rejected_by_server` | 篡改密文被拒 |
| `replayed_frame_is_rejected` | 重放被拒 |

## 0.4 自测发现并修复的缺陷（**e2e 的核心价值**）

e2e 测试**抓到两个会在生产中暴露的严重缺陷**，若只做单元测试将全部漏过：

| # | 缺陷 | 性质 | 症状 | 修复 |
| --- | --- | --- | --- | --- |
| 1 | 应答组装**漏拷贝 ticket 字段** | 静默功能失效 | 激活返回 `granted:true` 但客户端拿不到票据 → 离线降级失效 | 组装处补 `resp.set("ticket", ...)` |
| 2 | revoke / renew **持锁调用 log_line** | 运行时自死锁 | 请求**永久挂起**，日志里连记录都没有 | 调用前 `drop(st)` |

> 这两个缺陷都不是类型系统或编译器能发现的 —— 一个"看起来成功"，一个"卡住不报错"。
> 它们证明了**端到端测试不可省略**：单元测试全绿，产品依然可能是坏的。

## 1.4 关键测试技术：SSE 测试为何用原始 TCP

v1.5 的 SSE 集成测试**没有**用高层 HTTP 封装，而是自己拼请求、读原始 socket。
原因在踩坑 #25：服务端先 `write_all(header)` + `flush()`，再写第一帧，
内核会**立即把响应头单独发包**；若测试只 `read()` 一次，只能拿到 162 字节的
响应头，正文在另一个 TCP 段里 → 断言 `event: snapshot` 必然失败。

因此引入了两个辅助函数（`tests/integration.rs`）：

| 函数 | 作用 |
| --- | --- |
| `send_request_raw` | 循环读取直到超时或达上限（256 KiB / 3s），拼接完整响应 |

## 5.3 遗留风险（如实列明，不隐瞒）

| # | 风险 | 严重度 | 说明与缓解 | 计划 |
| --- | --- | --- | --- | --- |
| 1 | **审计链非密码学安全** | 中 | FNV-1a 无密钥，知晓算法者可整链重算。**能检出意外损坏与非恶意篡改，防不了蓄意伪造**。已在 02 结构文档"诚实的局限"段落明示 | 目标 9/12（v1.6） |

| 3 | **密钥丢失即数据不可恢复** | 中 | 加密的固有代价。缓解：`--encrypt-data` 默认关闭；文档明确"务必保管密钥"；提供 `--devkey-fingerprint` 核对 | 目标 14（v1.6） |

| 6 | 令牌密钥进程内不落盘 | 低 | 重启后旧令牌全部失效（属**预期行为**，更安全）；代价是用户需重新登录 | 设计如此 |

| 9 | SSE 占用常驻线程 | 低 | 32 路观看者 = 32 个常驻线程；校运会场景足够，但需评估 | 目标 3（v1.6） |

| 11 | UI 仍无自动化回归命令 | 中 | 实测靠临时脚本，未固化为 `make test-web`；改动仍需人工驱动浏览器 | 目标 4（v1.6） |
| 12 | 口令明文存 config.json | 低 | 无哈希；靠文件系统权限保护，本机场景可接受。**注意 `devkey` 已刻意不写入配置文件** | 目标 2（v1.6） |
