- ❌ **不拆分 `api.rs`**：用户指令是"修完全部 bug"。拆分是**重构**而非修复，

  决定权必须留给使用者（`--ignore-lock`）。

| 新增候选：**缓存 TTL 可配置** | 按需 | 当前默认 5000ms，前端可传 `ttl` 覆盖。多机同写同一数据文件的场景需更低 TTL 或 `nocache` |

| 新增候选：**接口版本化（`/api/v2/...`）** | 建议 v1.7（可选） | 若未来还需破坏性变更，应改为路径版本化，而非再次统一改契约 |

### v1.6.0 追加的 Non-Goal

- ❌ **不做多文件前端工程化**：不引入打包器 / npm 依赖 / 模块系统。
  理由：本项目交付形态是"单 exe + 资源内嵌"，任何前端构建链都会破坏它。
  深度重构在**单文件内分层**即可获得可维护性收益（见 `docs/02` §14.6）。
- ❌ **不做分布式 / 多实例限流**：限流器是进程内内存实现。
  理由：单机单进程是既定形态；跨进程限流需要共享存储，属过度设计。
- ❌ **不做响应缓存（服务端）**：只在前端做。理由：数据在本机，网络往返本就是 `127.0.0.1`，
  服务端缓存的收益远小于"数据可能陈旧"的风险。
- ❌ **不做接口鉴权细化（RBAC）**：仍维持"单口令 + 令牌"模型。
  理由：单机工具的"用户"实际只有一台机器前的老师，引入角色系统是无收益复杂度。

## 一、近期目标（v1.3 · 小版本优化）

### 目标 1：代码质量专项清理

**动机**：v1.2 完成后仍有 24 条编译警告（多为未使用导入与变量），
虽不影响功能，但会淹没真正的告警。

**验收标准**：
- `cargo build --release` 警告数降至 **0**；
- 保持 57 个测试全绿；
- 不改动任何业务行为（纯清理）。

---

### 目标 2：登录与角色权限

**动机**：当前系统**无任何鉴权**，任何能访问 `127.0.0.1:8765` 的人
都可删除项目、清空成绩。若要局域网多端使用，这是必要前提。

**验收标准**：
- 管理员 / 录入员双角色，录入页可加简单口令；
- 破坏性操作（删除、清空、导入）仅管理员可执行；
- 口令以加盐哈希存储，不明文落盘；
- 服务可选监听 `0.0.0.0`（默认仍为 `127.0.0.1`），并在启动时明确警告。

> **v1.5 进展（部分完成）**：框架层面的「令牌 + 二次确认」两级鉴权已落地
> ——写操作需 `Authorization: Bearer <签名令牌>`（12 小时有效、进程内随机密钥签发），
> 敏感破坏性操作额外需 `X-Confirm-Password`（预检 428 → 重放 200）。
> **仍未做**：① 角色区分（当前口令 = 管理员，无录入员角色）；② 口令哈希（当前为
> config.json 明文比对，靠文件权限保护）；③ `0.0.0.0` 监听告警。→ 顺延 v1.6。

---

### 目标 3：并发与稳定性加固

**动机**：当前 HTTP 每连接一线程，无上限；`write()` 持有 `Mutex` 期间
同步落盘，磁盘慢时会阻塞全部请求。

**验收标准**：
- 引入线程池或信号量限制并发连接数（默认 64，可配置）；
- 落盘改为「内存变更 + 异步刷盘」，避免阻塞请求线程；
- 提供压力测试报告（如 100 并发下的 P95 响应时间）。

> **v1.4/v1.5 进展（部分完成）**：并发上限 64 + 超限 503、连接读写 30s 超时已落地；
> **异步刷盘与压力测试报告仍未做**（`store.rs` 仍在 `Mutex` 内同步 `fs::rename`）。
> 但 v1.5 新增的 SSE 大屏引入了**新的并发关注点**：单连接长时间占用线程
> （最多 32 路观看者 = 32 个常驻线程），需在 v1.6 一并评估。

---

### 目标 4：前端自动化测试

**动机**：v1.2 的前端验证依赖人工 + curl，改动后无回归保护。

**验收标准**：
- 引入轻量断言脚本（Node 原生，不引入 npm 依赖）；
- 覆盖 6 个页签的核心交互路径；
- 集成到 `cargo test` 之外的一条独立命令（如 `make test-web`）。

> **v1.5 进展（部分完成）**：v1.3–v1.5 三轮迭代均以真实 Chromium 自动化驱动
> 完成浏览器实测（v1.5 共 12 个场景），但**脚本未固化为可重复执行的命令**，
> 每次靠临时脚本。→ v1.6 应把实测脚本沉淀到 `tools/webtest/`。

## 二、中期目标（v2.0 · 结构性重构）

**动机**：`api.rs` 约 2900 行，占全部 Rust 源码的 50%+，已到维护性拐点。

- 路由注册集中在 `api/mod.rs`，handler 分散到各子模块；
- **对外 API 与路由表完全不变**（扩展无感知）；
- 拆分后测试全绿，且新增模块边界测试。

## 五、v1.5 新增候选目标详解

### 目标 9：审计链接入 HMAC-SHA256

**动机**：v1.5 的哈希链用 FNV-1a 64 位，**能检出意外损坏与非恶意篡改，
但无法防伪造**——攻击者知道算法即可重算整条链（无密钥）。
此局限已在 `02_结构文档.md` 「诚实的局限」段落明示，不隐瞒。

**验收标准**：
- 密钥从 `data/.audit_key` 读取（首次启动生成，权限 0600）；
- 或改用标准库外的 `sha2` + `hmac`（需评估是否属最小依赖例外）；
- 提供 `--audit-key <path>` 参数；
- 旧链（FNV 格式）**自动识别并保留可验证**，新条目用新算法（向后兼容，规则 12）。

### 目标 10：大屏破纪录动画 + 排行滚动

**动机**：v1.5 大屏是静态列表刷新，视觉冲击力不足。

**验收标准**：
- 新破纪录事件触发 CSS 动画（金光扫过 / 缩放脉冲），可在大屏远端看到；
- 项目榜超过 8 行时自动逐行滚动；
- 动画不影响 SSE 吞吐（纯前端 CSS，不增加帧率）。

### 目标 11：推荐权重可视化调参面板

**动机**：`0.70/0.20/0.10` 三权重写死。不同项目特性不同——
短跑重「最好成绩」，长跑重「稳定性」，教师应有调整权。

**验收标准**：
- 设置页滑块调节三权重（和为 1.0 的约束实时校验）；
- 权重存入 `data/settings.json`，`/api/smart/recommend` 支持查询参数覆盖；
- 推荐理由文案随权重变化（当前已实现 `reason` 动态生成，改造成本低）。

## 六、明确不做（Non-Goals）

为避免过度设计，以下方向**本阶段明确不做**：

- ❌ **多租户 / 多校共用**：定位是单校单机工具，引入租户模型得不偿失。
- ❌ **云部署 / 容器化**：运动会场景在网络不稳定的操场，本地运行才是最优解。
- ❌ **移动端原生 App**：前端已响应式，浏览器足够。
- ❌ **引入前端框架（React/Vue）**：与「零构建、双击即用」的部署理念冲突。
- ❌ **为追求「零依赖」而自实现 xlsx**：实现成本远超收益，一个 crate 是合理取舍。

### v1.5 追加的 Non-Goal

- ❌ **AI 大模型在线推荐**：v1.5 的「智能推荐」刻意做成**可解释的确定性加权公式**
  （`0.70 成绩优势 + 0.20 稳定性 + 0.10 参与度`），每项给出中文理由。
  不接入在线模型——运动会现场常无网络，且教师需要理解「为什么推荐这个学生」，
  黑箱推荐在校园场景不可审计。
- ❌ **SSE 换 WebSocket**：大屏是**单向推送**（服务端 → 浏览器），
  SSE 比 WebSocket 更简单（无需握手升级、无自定义协议、浏览器自带重连），
  且可复用现有 HTTP 栈。引入 WebSocket 属过度工程。
- ❌ **自实现密码学哈希**：目标 9 若做，必须用成熟实现（`sha2`/`hmac` crate）
  或调用系统库，**绝不自行实现 SHA-256**——密码学自研是反模式。

### v1.5.2 追加的 Non-Goal

- ❌ **在本地训练中文语音识别（ASR）模型**：用户曾提出这一设想，经评估**明确不做**。
  本地训练需要**数千小时标注语料 + GPU**，训练与推理栈会引入数十 MB～GB 级模型文件，
  与「单 exe 约 4.5 MB + 零新增依赖 + 离线单机」三条硬约束**直接冲突**；
  且以单机沙箱的算力与语料量，训练结果**不可能达到可用精度**。
  v1.5.2 改用**浏览器内置 Web Speech API**（引擎由 OS/浏览器提供），零依赖、零体积。**如实告知用户。**
- ❌ **接入云端 ASR 商业 API（自建 Key）**：会让产品**依赖外部账号与网络配额**，
  与校园"离线单机、长期免维护"的定位不符。浏览器内置方案由用户的浏览器/系统自带凭据驱动，
  **项目本身不持有任何云端密钥**，这是更干净的边界。
- ❌ **多条语音命令 / 复合语义解析**：v1.5.2 只做**纯文本填入 + 封闭别名表精确匹配**。
  不做"张三跳远13秒5"这类整句解析——校园场景下**误解析的代价高于多按几次按钮**。

## 六、v1.5.1 新增候选目标详解

### 目标 12：密码学原语统一升级（`sha2` + `hmac` + `argon2`）

**动机（最重要）**：v1.5.1 引入了四处安全原语，**全部为自实现 FNV-1a 64 位**：

| 位置 | 现用算法 | 风险 | 应换为 |
| --- | --- | --- | --- |
| `core/audit.rs` 审计链 | `fnv1a64` | 可离线重算整链，无法防伪造 | `hmac-sha256` |
| `core/api.rs` 令牌签名 | `fnv1a64` | 32 位输出空间小，理论可碰撞 | `hmac-sha256` |
| `core/license.rs` 密钥指纹 | `slow_hash`（20 万轮 FNV） | 弱 KDF，GPU 可高速枚举 | `argon2id` |
| `core/vault.rs` 数据加密 | FNV 派生 XOR 流 | **不是流密码**，密钥流可预测 | `chacha20poly1305` |

**为什么 v1.5.1 没做**：项目立项时的硬约束是「**最小依赖**」——
v1.5.1 在零新依赖前提下已经把"提高门槛"做到了当前的合理上限，
并把真实局限**诚实写入文档**（`docs/12`、README、使用说明三处明示）。
继续自研密码学才是真正的反模式。

**验收标准**：
- 新增 `sha2` + `hmac` + `argon2`（或 `chacha20poly1305`）四个 crate；
- 审计链、令牌签名、密钥指纹、数据加密四处**全部替换**；
- 提供**旧格式自动识别与迁移**（读旧 FNV 链/旧 FNV 密文，写新格式）；
- 更新 `docs/08_依赖清单.md` 并解释每项依赖的不可替代性；
- 更新 `docs/12` 的强度声明，撤掉"非密码学安全"的诚实声明段落。

### 目标 13：密钥轮换与多密钥管理

**动机**：当前 `LICENSE_FINGERPRINT` 是**编译期常量**，换密钥要改源码 + 重新编译，
学校 IT 人员做不到。且只能有**一个**密钥（无法区分"这台机器的调试者"与"厂商售后"）。

**验收标准**：
- 支持外部密钥文件（如 `keys.json`，含多个 `{name, fingerprint, role}`）；
- 运行期热加载，无需重编译；
- 支持密钥轮换：旧密钥保留一段时间（宽限期），到期自动失效并写审计；
- 提供 `--devkey-rotate` 类命令生成新指纹。

### 目标 14：加密文件的可迁移导出

**动机**：v1.5.1 加密后，**换机器必须带原密钥**，密钥丢失即数据不可恢复。
这在"运动会前一天换笔记本"的场景下是硬伤。

**验收标准**：
- 提供 `--rekey <旧key> --newkey <新key>` 或管理页"重新加密"按钮；
- 导出为指定密钥加密的文件（用于迁移到另一台机器）；
- **必须**有明确的二次确认（重新加密写错密钥 = 数据永久丢失）；
- 导出过程写审计。

### 目标 15：开发者模式访问审计告警

**动机**：当前只有**成功解锁**才写审计。若有人反复用错误密钥尝试解锁
（或从局域网尝试），系统**完全无感**——因为错误密钥是"静默降级"（这是刻意设计，
但也意味着攻击探测不可见）。

**验收标准**：
- 在**不削弱静默降级**的前提下，记录"解锁尝试"事件（只记**次数与来源**，不记密钥）；
- 连续 N 次失败 → 写 `WARN` 日志 + 前端诊断页显示"检测到 N 次失败尝试"；
- 保持"密钥错误本身不返回任何差异"这一原则不变（只统计外部可观测的行为）。

## v1.8.0 目标：服务端授权机制

| # | 目标 | 达成 | 证据 |
| --- | --- | --- | --- |
| 1 | 服务端校验密钥，区分持久/临时 | ✅ | `store::KeyKind`、`issue(kind,...)` |
| 2 | 无网络转离线模式，查历史持久密钥 | ✅ | `client::offline_decision()` 四步判定 |
| 3 | 持久密钥时效内允许使用 | ✅ | 持久优先于临时；`expire_at` 校验 |
| 4 | 密钥基于机器指纹 + 哈希 | ✅ | `hwid::fingerprint()` + `slow_hash` |
| 5 | 客户端→服务端走加密协议 | ✅ | `channel.rs` 流密码 + MAC + 防重放 |
| 6 | 三个包：源码/发行/服务器 | ✅ | `build.sh` → `build_out/` |
| 7 | 发行包无源码 + 混淆加密 | ✅ | 符号剥离 + 盐混淆 + 路径改写 |
| 8 | 不能白嫖（防盗拷） | ✅ | 一机一码 + 远程吊销；e2e 验证 |
