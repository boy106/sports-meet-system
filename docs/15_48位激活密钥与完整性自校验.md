# 15 · 48 位激活密钥与完整性自校验（v1.9.0）

> 本文对应三项新增手段：
> **① 48 位混合字符激活密钥**（数字/字母/符号/汉字交替，内嵌加密的授权参数）、
> **② 二进制完整性自校验**（改一个字节即被发现）、
> **③ 校验逻辑与业务请求交织**（授权复核长在门禁上，不是独立开关）。
>
> 与既有体系的关系：服务端授权（docs/13）与试用密钥（docs/14）**照旧工作**；
> 本文新增的是**纯离线**路径 —— 不依赖授权服务器，断网可用。

---

## 一、48 位密钥长什么样

```
8P^丰3C/勇6O[堘3f;刏3Q[婘2O:嚓5l^儣5C?媑2c~嘬8R,墝8m}丣4e+倰
↑ ↑ ↑ ↑
数 母 符 汉
```

48 个字符按 **数字 → 英文字母 → 符号 → 汉字** 四位一循环，共 12 组。
字符表刻意避开空格与不可打印字符，可以安全地打印、抄写、微信转发。

### 1.1 为什么是这个形状

* **人类可读可抄写**：学校管理员要把密钥发给老师，电话里能念、
  纸上能抄。纯 hex/base32 抄错一位就废，汉字组让"错位"更容易被肉眼发现
  （"这一位应该是汉字，怎么是个字母？"）。
* **容量经过计算**：每组容量 10×52×32×3500 = 58,240,000 ≈ 25.8 位，
  12 组合计 ≈ 309.5 位；有效数据占 38 字节（304 位），
  **余下的约 5.5 位恒为零**，兼作格式校验（抄错极难凑出零）。

### 1.2 里面封装了什么（全部加密）

| 字段 | 宽度 | 含义 |
| --- | --- | --- |
| 魔数 / 版本 / 类型 | 2 B | 格式标识 + trial/standard/pro/edu/demo |
| 机器指纹摘要 | 6 B | 绑定本机（换机连解密都失败） |
| 生效日期 | 4 B | Unix 天；0 = 立即生效 |
| **到期日期** | 4 B | Unix 天；`0xFFFFFFFF` = 永久 |
| **累计使用时长上限** | 3 B | 秒；0 = 不限（约 4.6 万小时） |
| **使用次数上限** | 2 B | 次；0 = 不限 |
| **功能位图** | 2 B | 基础/导出/智能解析/赛程编排/打印/批量 |
| 密钥编号 | 3 B | 24 位，事后追溯批次用 |
| 认证标签 | 10 B | 80 位 AEAD 标签（防篡改） |
| CRC-16 | 2 B | 抄录错位的第一道筛查 |

封装方式：**密文(26B) + 认证标签(10B) + CRC16(2B)** 按混合进位制编成 48 字符。
加密与认证密钥由「**二进制内置主密钥 + 机器指纹**」派生 —— 指纹参与派生是
硬约束：换机器时不是"指纹字段不匹配"，而是**连解密都失败**，没有伪造窗口。

## 二、签发：密钥从哪来

签发脚本 `tools/issue_license.py`（**只进源码包，绝不进发行包**）：

```bash
# 1) 生成主密钥（与 issuer.key 同一保管级别，权限 600）
python3 tools/issue_license.py keygen-secret --out ./keys
#    产出 keys/aim.secret —— 构建时经 build.rs 掩码注入二进制，
#    源码包与发行包中均无明文

# 2) 给某台机器签发（指纹由客户端「诊断 → 软件授权」页展示/复制）
python3 tools/issue_license.py issue-key \
    --secret ./keys/aim.secret \
    --hwid 7f3a91c2e4b8d0a6 \
    --days 365 --kind pro \
    --uses 200 --seconds 72000 \
    --features all --out my.key

# 3) 自检（不修改任何东西）
python3 tools/issue_license.py verify-key \
    --secret ./keys/aim.secret --hwid 7f3a91c2e4b8d0a6 --key "<48位密钥>"
```

Python 与 Rust 两侧实现**逐字节一致**，由一把跨语言金向量测试守着
（`keyfmt.rs` 的 `cross_language_vector_matches_python`：同一把测试主密钥、
同一组参数，两边产出的 48 个字符必须完全相同）。任何一边跑偏
（字节序/派生标签/进位制/字符表），该测试即红，历史密钥不会悄悄失效。

### 2.1 主密钥为什么不写死在源码里

源码包是交付物之一。任何写进 `.rs` 的秘密都会随源码包分发。
因此主密钥放在 `keys/aim.secret`（与 Ed25519 私钥 `keys/issuer.key`
同一保管级别），由 `build.rs` 在构建时读取、XOR 掩码后注入二进制。
缺失时模块整体停用（返回明确错误），不影响程序其余功能 ——
所以**源码开发不需要密钥也能编译测试**。

## 三、使用配额：本机计量

密钥里可以限"用多少次"和"用多少小时"。这两个计数器放在本机：

* **3 个真实副本**（文件名由指纹派生，攻击者不容易猜到位置），
  每次读档取 **max** —— 删掉一个副本不能重置计数；
* **6 个诱饵文件**（魔数不同，内容随机）—— 让"找文件"的成本变高；
* 文件内容加密并绑定指纹，**换机器连计量文件都读不了**。

累计时长用**惰性心跳**计量：由状态查询/业务请求驱动
（门禁复核每 15 秒一次），单次最多累加 1 小时 ——
既覆盖"程序开着但页面没刷新"的空闲，也防止改动系统时钟造成的暴涨。

### 3.1 诚实的边界

纯客户端计量**不是**数学意义上不可绕过：能完整逆向二进制的对手
可以提取主密钥、自行签发、改写计量文件。这三项手段（密钥 AEAD、
完整性自校验、运行时复核）的实际效果是**把门槛抬到"不值得绕"**：
对"白嫖"场景，改密钥/抄别人密钥/删计量文件全部无效；
对"就是要破解"的场景，请看第四节的诚实声明。

## 四、完整性自校验（手段 2）

二进制里内嵌一段 **160 字节数据区**（build.rs 从缓存组装）：

```
[0..8)     起始魔数 "SMI1DATA"（同时是运行期的搜索锚）
[8..136)   8 段期望哈希（每段 SHA-512 前 16 字节）
[136..144) 8 个交叉指纹（相邻段异或后的字节和）
[144)      盖章标志：1 = 已盖章（真实期望值），0 = 基线（占位符）
[145..152) 保留（零）
[152..160) 结束魔数 "DATA1SMI"
```

运行期校验：**先在文件里定位魔数（锚取自数据区自身，逐个候选校验
「结束魔数 + 交叉指纹」，假候选通过概率 2^-64）、把数据区整段掩码
归零**，再对全文件均分 8 段算哈希并比对。交叉指纹额外保证"期望数据
自身"没被改（把某段哈希改掉，交叉校验立刻失败）。

### 4.1 自指悖论与不动点解法

"哈希值自己也在被哈希的文件里"——直接嵌入会让校验永远不过。
解法是把数据区视为**透明区**：期望值嵌入的位置 == 被掩码掉的位置，
于是嵌入真实期望值**不改变掩码后的内容**，两遍构建达到不动点：

```text
① cargo build --release        （BLOB 占位符 + 标志 0 → 基线模式，只算不判）
② integrity_stamp.py           对①的产物掩码后算期望值 → 写缓存
③ touch build.rs && 再构建     嵌入真实期望值 + 标志 1（掩码后内容与①相同）
④ integrity_stamp.py --verify  复算 + 缓存 + 内嵌值三方比对，必须一致
```

基线模式（自行编译、开发期）**不阻断**：没有期望值可比，
`verify_self` 只报不算。发行构建由 `build.sh` 保证走完四步，
并在打包前最后一道断言"二进制必须已盖章"。

### 4.2 实测踩过的三个坑（改这块代码前必读）

v1.9.0 开发期**全部实测命中**，每个都曾让"不动点" silently 失效：

1. **数据区必须是 `#[used] #[link_section] static`，不能是 `const`**。
   `const` 数组的读取点全是常量索引 → LTO 直接把数组折叠消除，
   二进制里只剩 `mask_blob` 自己的比较字面量（实测两个魔数相距
   104 字节），数据区根本不在文件里 —— 盖章直接失败。
   `#[used]` 把符号钉进 `llvm.compiler.used`，LTO 也保留。
2. **读取必须走 `read_volatile`**。否则期望值被折成比较指令里的
   立即数：第一遍（占位符）与第二遍（真实值）编译出的**代码不同**，
   掩码后文件仍然不同，不动点被破坏，`--verify` 永远红。
3. **必须连 GNU build-id 笔记一起掩码**。链接器默认写
   `.note.gnu.build-id`（20 字节），它是对**全部节内容**算的哈希：
   BLOB 内容两遍构建间不同 → build-id 也不同 → 那 20 字节随 BLOB
   变化，只掩码数据区仍达不到不动点（实测：段 0 复算永远不符，
   且报错完全不提示真正原因）。解法：把笔记的 desc 也归零
   （`mask_build_id`，头部静态不动）。

### 4.3 它与业务的关系（手段 3）

完整性校验**没有独立开关**，而是长在三个业务位置上：

1. **激活密钥时**（授权体系入口被污染 → 后面全部不可信）；
2. **每次授权判定**（有授权物时）；
3. **门禁复核**（见下节，15 秒节流）。

## 五、运行时复核：过期必须"现在"生效

启动时算好的授权结论是**快照**。一份 3 天有效的密钥在第 4 天、
一个 100 次的配额在第 101 次启动时，如果不再复核，长跑的服务器
会凭过期快照一直放行 —— "有效时间/使用时间/使用次数"全部落空。

因此 http 门禁在每个业务请求前都过 `AuthManager::recheck_gate()`：

* **每次必查（免费）**：密钥日期时效（纯整数比较）；
* **15 秒节流**：配额（读写计量文件）、离线许可（Ed25519 验签）、
  试用（读分散记录）、完整性（读整个二进制）。

复核失败时 `last` 会被改写为拒绝 —— 诊断页、状态接口、403 响应
三者看到的是同一个结论，不会出现"界面说能用、接口说不能用"。

## 六、三条路径怎么配合

```
                     ┌─ 非对称许可文件 license.lic（Ed25519，不可伪造，最强）
   授权放行 ────────├─ 48 位激活密钥 license.key（本文，纯离线，AEAD）
                     ├─ 在线票据 data/.license（服务端签发，可吊销）
                     └─ 内置试用密钥（30 分钟，一次性）
```

优先级从上到下。文件许可与密钥都不需要联网；
服务端不可达时自动降级，**断网不影响已授权用户**。

## 七、诚实的局限（**必读**）

1. **48 位密钥不是"数学不可伪造"**：容量装不下 Ed25519 签名，
   采用 AEAD 是工程折中。能完整逆向二进制的对手可提取内置主密钥
   后自行签发。对"不可伪造"有硬要求的场景，请用 `license.lic`
   （私钥离线、客户端只验不签）。
2. **完整性自校验防"改文件"，不防"改进程"**：patch 过的二进制
   跑起来的就是 patch 后的代码 —— 自校验提高的是"改动不留痕迹"的
   成本，不是绝对屏障。
3. **本机计量可被彻底清除后重置**（试用同理）：要硬一次性，
   开 `TrialPolicy::require_online_confirm` 由服务端登记。
4. 以上每一项都在**抬门槛**。防盗版的目标是让"白嫖"比"购买"更麻烦，
   不是制造一个理论上不可攻破的系统 —— 后者在纯客户端上不存在。
